# Ternary Bonsai 2.5 27B vs Ternary Bonsai 2 27B on the GTX 1070 Ti

Generated by `bench/bonsai25_vs_2.sh` (summary: `bench/bonsai25_vs_2_summary.py`). Engine runs: temp 0, seed 42, `taskset -c 0-3`, one GPU program at a time, VRAM cap 7373 MiB. Peak VRAM = highest `nvidia-smi` sample, RSS = max resident set of the engine process. A dagger marks a Bonsai 2 number taken from an earlier recorded run (other session) instead of this run.

## Summary

- **Decode speed.** Without MTP, Bonsai 2.5 runs at 0.97x to 1.00x the speed of Bonsai 2 at the same context (section 3, all contexts where its LM head stays on the GPU).
  At ctx 131072 the 2.5 LM head no longer fits the VRAM cap and runs on the CPU (0.37x). With `--fit-ctx-for-gpu-head 1` the context drops to 126976 and decode is 8.93 tok/s.
- **VRAM and RAM.** Bonsai 2.5 stores the 96 `ssm_alpha`/`ssm_beta` tensors as F32 instead of BF16, which adds 45.0 MiB of weights. Peak VRAM is about that much higher; RSS is the same. The engine reads these tensors as F32 (no conversion, numerics unchanged).
- **MTP.** Best ChatML coding run: Bonsai 2 28.45 tok/s (b2_uq4), Bonsai 2.5 28.62 tok/s (b25head). The uq4 head was trained for Bonsai 2 and accepts fewer drafts on 2.5; on 2.5 its own head (built-in or extracted as a sidecar) is the fastest choice. Every MTP row with output is lossless (same ids as without MTP).
- **Quality.** Bonsai 2.5 is further from the Qwen reference: WikiText-2 PPL 10.245 vs 8.000, KLD 0.5476 vs 0.3561. Task scores, 2.5 minus 2: hellaswag -1.0, winogrande +2.0, arc +0.0, mmlu -2.7 points, inside the noise of these small subsets (standard error 3 to 5 points). These numbers come from llama.cpp (`prism` build), not from qwen38-engine, so the difference belongs to the model weights, not to this engine.
- **Behaviour.** Bonsai 2.5 is chat tuned: on raw text prompts it often ends at once with EOS (5b), so the ChatML rows (5a) are the fair comparison.

# Experiment log: branch `exp/ternary-bonsai-27b-eval` (2026-11-17)

Evaluation of PrismML **Ternary Bonsai 2 27B** on the GTX 1070 Ti against the project baseline **Qwen3.8-27B-UD-Q4_K_M**.
Every attempt is recorded in order: reason, command, output, decision. Failed attempts have their own section with the root cause and the fix.
Summary tables: `bench/results/ternary_bonsai_comparison.md`. Every run with its exact peak VRAM: `bench/results/bonsai/RUNS.md` (generated by `bench/bonsai_ledger.py`).
Figure: `docs/figures/50_ternary_bonsai.svg`.

## 2. Failed and rejected attempts: root cause and fix

| ID | Attempt | What happened (exact) | Root cause | Fix |
|---|---|---|---|---|
| F1 | Every layer on the GPU at the default ubatch 512 | 7791 MiB (llama-bench), 7647 MiB (server at 4K f16) | weights 6921 MiB leave 452 MiB; KV + state + compute buffer need more | `-ub 128` and q4_0 KV: 7371 MiB (2 MiB margin); longer contexts move layers to the CPU |
| F2 | f16 and q8_0 KV at 32K with 59 GPU layers | f16: `allocating 1920.00 MiB on device 0: cudaMalloc failed: out of memory`; q8_0: 7855 MiB | KV of 15 GPU attention layers at 32K: f16 1920 MiB, q8_0 1020 MiB | q4_0 (540 MiB, 7343 MiB) or iso3 (375 MiB, 7167 MiB) |
| F3 | First 64K prompt | `request (69447 tokens) exceeds the available context size (65536 tokens)` | my token estimate per synthetic line (27) was low: lines with larger numbers take about 30 tokens | the bench script now sizes the prompt with the server's own `/tokenize` |
| F4 | 64K prompt, second try | prefill done (pp 49.07) but `predicted_n = 1` | greedy decoding ended the synthetic text with the end token right away | requests send `ignore_eos: true`; the first result is kept as `_eos` |
| F5 | 128K with `-ngl` 51/52 (iso3) and 48 (q4_0) | 7739 / 7847 / 7899 MiB | the first calculator assumed a constant runtime overhead; measured, it grows by about 6.1 KiB per context token (about 1.08 GiB at 128K) | `-ngl 48` (iso3) and 43 (q4_0) fit; calculator uses the measured model |
| F6 | PTQ1_0 every layer on the GPU at 64K | load 7121 / 7245 MiB, but peak 7471 / 7595 MiB | the fork allocates about 350 MiB more at the first request | `-ngl 62` (7361 MiB); decode drops to 6.77 tok/s (two layers and the output on the slow release CPU path) |
| F7 | Calculator v1 (zero overhead) | predicted Q2_0 + iso3 up to 24.7K tokens with every layer on the GPU | overhead ignored | v2 with the measured overhead: about 400 tokens; matches F1 |
| F8 | Benchmarks during downloads | (avoided) | downloads write into the page cache and can evict the CPU layers of Qwen and of partly offloaded Bonsai runs | Qwen runs waited for the download; the PTQ1_0 download was paused with SIGSTOP during sensitive runs and resumed with SIGCONT |
| F9 | 128K full prompt | not run | about 1 hour of prefill at 33-41 tok/s | 128K reported as capacity plus speed at a short depth |
| F10 | `PTQ1_0` perplexity, ubatch 512 and 128 | `CUDA error: out of memory` in `cuMemCreate` on the first batch (peak 6579 / 6163 MiB) | perplexity needs logits for every token; for a batch the fork dequantizes the 248320 x 5120 output matrix to F16 (2.37 GiB) | `-ub 8` keeps the batched mat-vec path: 5691 MiB, 8.3 s per chunk |
| F11 | `Q2_0` HellaSwag with every layer on the GPU | peak 7847 MiB | the multiple-choice modes run 4 sequences in parallel, each with a 150 MiB DeltaNet state | `-ngl 60`: 7279 MiB |
| F12 | `Q2_0` ARC-Challenge, 299 tasks | `task 210 requires a higher -np|--parallel value (at least 5)`, no final score | some ARC items have 5 answer choices | `-np 5`, `-ngl 59` and N = 298 (random draw, so the prefix property holds): 7307 MiB |
| F13 | VRAM samples after stopping a run early | `nvidia-smi` samplers kept running and wrote into later runs' files | killing the bench script did not stop its background sampler | `trap ... EXIT` in `bench/bonsai_intel.sh`; peaks taken from the line each run prints when it ends (`intel/run_lines.txt`) |

No kernel test failed; the ternary kernel passed on the first build. F10-F13 are from the intelligence runs (steps 28-37).

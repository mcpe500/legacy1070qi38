# WebUI, server, and parity benchmark

## Server contract (src/server/)
- Library: cpp-httplib (single header, C++). This is a decision: the brief allows cpp-httplib or axum.
  cpp-httplib keeps one toolchain (C++ with the CUDA build). Revisit only if measured memory or
  features require it.
- Endpoint: `POST /v1/chat/completions`, OpenAI-compatible request and SSE response.
- Request fields: `model`, `messages`, `stream`, `temperature`, `top_k`, `top_p`, `min_p`,
  `repeat_penalty`, `presence_penalty`, `seed`, `max_tokens`, and `mtp_steps` (integer 0 to 3,
  custom field, 0 disables MTP).
- Stream format: `data: <json>\n\n` per chunk with `choices[0].delta.content`, then `data: [DONE]\n\n`.
- Telemetry: the final chunk carries a custom `x_telemetry` object with `pp_tps`, `tg_tps`, `ttft_ms`,
  `mtp_accept_pct`, `vram_mib`, `rss_mib`. A `GET /metrics` endpoint returns the same fields for polling.
- Memory budget of the server process: under 15 MB RSS, measured with `/usr/bin/time -v`.

## WebUI (webui/index.html, one file, no build step)
- High-contrast dark card layout. No Node, React, or CDN dependency.
- Streaming chat view. The think-tag parser:
  - A `<think>` block renders as a collapsible card. The default state is collapsed.
  - Tags can split across SSE chunks. Hold back up to 7 trailing characters that could start `<think>`
    or `</think>` (the longest tag is 8 characters), and emit them only when they cannot be a tag prefix.
  - Test with chunk boundaries at every position of a sample string (see tests/).
- Sampler panel: `temperature`, `top_k`, `top_p`, `min_p`, `repeat_penalty`, `presence_penalty`,
  `seed`, `max_tokens`, `mtp_steps` (0 to 3). Each change sends the next request with the new values.
- Telemetry bar: pp tok/s, tg tok/s, TTFT (ms), MTP acceptance (%), VRAM MiB, DDR4 RSS MiB.

## 3-stage verification protocol (against llama.cpp)
**Stage A, logit and token parity (temp = 0, seed = 42).**
- Reference: llama.cpp built from the fork (`LEGACY_LLAMA_BIN_DIR`, see AGENTS.md), with the same GGUF,
  the same KV type, and the same MTP setting.
- Prompts: short and multi-turn set, fixed in tests/prompts.txt.
- Pass: greedy token sequences identical for the whole prompt set, and top-k logits with cosine
  similarity > 0.998 at every generated position.
- Caveat: llama-server's `n_probs` returns probabilities for the top tokens, not raw logits. Raw logits need
  a dump tool. Decide the method in stage 2.
- Caveat: MTP output is not bit-identical to non-MTP output (PR #38). Compare like with like.

**Stage B, headless UI and API.**
- `curl -N` against `POST /v1/chat/completions` with `stream: true`: count `data:` lines, check `[DONE]`,
  and check that the concatenated deltas equal the non-streamed response for the same seed.
- Headless browser test: Playwright with Node. Node is not installed on this machine yet (setup.sh
  section 6). Until it is, stage B covers only the curl part.
- Pass: SSE streams, `<think>` folds, and a sampler change reaches the server payload.

**Stage C, sequential benchmark (bench/compare_llamacpp.sh).**
- Standard workload: 512-token prompt, 256-token decode, greedy.
- Order, never concurrent: start llama-server, wait for readiness, warm up, measure, stop it, confirm the
  GPU is empty (`nvidia-smi --query-compute-apps`), then start the engine and measure the same way.
- Tools: hyperfine (user-local 1.12.0, `~/.local/bin/hyperfine`), `/usr/bin/time -v` for RSS, and
  `nvidia-smi` sampling for VRAM peak. Use `taskset -c 0,1,2,3` for both sides.
- Output: a Markdown table with pp tok/s, tg tok/s, MTP accept %, peak VRAM MB, and peak DDR4 RSS MB,
  with the exact command lines and llama.cpp commit in the header.
- Report medians of at least 5 runs after warm-up. Report the clock and throttle state of the GPU if
  it changed during the run (the earlier llama.cpp runs showed `sw_power_cap` throttling).

## Reference numbers (llama.cpp, measured in the legacy repo)
- Hybrid Q4_K_M with `-ot` FFN 17..64: 2.85 tok/s (bench, short context).
- ctx 16384 with KV iso3 and `-ot` FFN 15..64: 2.61 tok/s. MTP depth 1 at the same setting: 2.37 tok/s.
- Quality (KLD vs Q4_K_M, f16 KV, wikitext-2): KV q8_0 0.0005, KV q4_0 0.0024, KV iso3 0.0102.
